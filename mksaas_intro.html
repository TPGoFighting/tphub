Deep Dive

拆开看：技术架构与「里面有什么」

下面三块讲清它为什么能「克隆即用」——目录结构、环境变量契约，以及一次真实 AI 调用该怎么写。

① 目录结构：App Router 的全栈骨架

典型的 MKSaaS 仓库遵循 Next.js 13+ App Router 约定。app/ 放路由与页面，lib/ 放认证/支付/AI/数据库四类客户端，components/ 放 UI，prisma/ 或 db/ 放数据层。

# 典型 starters 目录（截取）
mksaas-starter/
├─ app/                  # App Router 路由与页面
│  ├─ (auth)/           # 登录/注册路由组
│  ├─ api/              # Route Handlers（AI、webhook）
│  └─ dashboard/        # 登录后才能进的后台
├─ components/           # UI 组件
├─ lib/                 # 四类基础设施客户端
│  ├─ auth.ts           # 会话与鉴权
│  ├─ db.ts             # 数据库连接
│  ├─ payments.ts       # 支付/订阅
│  └─ ai.ts             # AI 供应商封装
├─ prisma/ 或 db/      # schema 与迁移
└─ .env.example          # 环境变量契约

② 环境变量契约：一份 .env.example 决定能跑起来

四类模块各自需要的密钥都集中在 .env.example 里。本地复制成 .env.local 填值即可，生产环境在 Vercel 后台一一对应填写，无需改代码。

# .env.example —— 四类模块的密钥契约
# 数据库
DATABASE_URL=postgresql://user:pass@localhost:5432/mksaas

# 认证（NextAuth 风格）
NEXTAUTH_SECRET=replace-with-random-string
NEXTAUTH_URL=http://localhost:3000
GOOGLE_CLIENT_ID=your-oauth-client-id
GOOGLE_CLIENT_SECRET=your-oauth-secret

# 支付（Stripe）
STRIPE_SECRET_KEY=sk_test_xxx
STRIPE_WEBHOOK_SECRET=whsec_xxx

# AI 供应商（可切换）
OPENAI_API_KEY=sk-xxx
# ANTHROPIC_API_KEY=sk-ant-xxx   # 换成 Claude 时启用
💡 关键设计：密钥只存在于环境变量，代码里永远 process.env.XXX 引用。这既满足安全审计（无硬编码密钥），也让同一份代码在本地、预览、生产之间靠变量隔离无缝切换。

③ 一次真实 AI 调用：封装层怎么用

MKSaaS 的 lib/ai.ts 把供应商差异屏蔽掉。业务里只调统一接口，错误处理与重试集中在一处，避免每个页面各写一遍 SDK。

// app/api/chat/route.ts —— 一个 Route Handler 里的 AI 调用
import { getAIClient } from "@/lib/ai";

export async function POST(req: Request) {
  const { prompt } = await req.json();
  try {
    // 统一接口：换供应商只改 .env，不碰业务代码
    const ai = getAIClient();
    const res = await ai.complete({
      model: "gpt-4o-mini",
      messages: [{ role: "user", content: prompt }],
    });
    return Response.json({ ok: true, text: res.text });
  } catch (e) {
    // 错误在封装层已结构化，这里只透出安全信息
    return Response.json({ ok: false, error: "AI 调用失败" }, { status: 500 });
  }
}

FAQ

常见问题

关于它是什么、适合谁、怎么用——挑最常被问到的几条。

01

MKSaaS 是开源库还是付费模板？

＋
它是付费的 SaaS 启动模板（starter kit），不是 npm 包。你购买或获得授权后克隆仓库到本地，在自己的项目里改装。核心卖点正是「买来即改、省去搭基建」，因此源码通常不在公开仓库，细节以官网与授权协议为准。
02

它和普通「Next.js 教程项目」差在哪？

＋
普通教程项目只演示单个功能；MKSaaS 把认证、支付、数据库、AI 四类模块做成可配置的完整拼图，并给出多租户、权限、计费的参考实现。也就是说，它直接对齐「能收钱的产品」而不是「能跑的 demo」。
  • 认证：登录/注册/OAuth 已接好
  • 支付：订阅与一次性付费的 webhook 雏形
  • 数据：迁移脚本 + ORM 配置就绪
  • AI：供应商切换只改环境变量
03

没有后端经验能上手吗？

＋
能，但前提是会基本的 React/Next.js。模板的难点（鉴权、计费状态机、AI 错误边界）已被封装，你主要做两件事：填环境变量与写自己的页面与业务逻辑。它同时也是学习企业级 SaaS 架构的优质样本。
04

支付和 AI 供应商能换吗？

＋
可以。数据库、认证、支付、AI 四类都通过 lib/ 下的客户端与 .env 解耦：
  • AI：OpenAI 与 Claude 等通过改 API Key 与 model 名切换
  • 支付：Stripe / Lemon Squeezy 等常见网关可选接入
  • 数据库：Postgres 为主，ORM 可随配置调整
具体支持列表请核对官网当前版本，模板会随生态更新。
05

怎么从本地跑到生产环境？

＋
本地 npm run dev 验证功能；把仓库推到 GitHub 后在 Vercel 导入，环境变量在 Vercel 后台逐一填写，即可自动部署。模板已内置构建与 CI 脚本，连仓库即上线，无需自己搭流水线。
06

适合用来做什么产品？

＋
任何「要登录、要收钱、要用 AI」的 Web 产品都合适：AI 写作/绘图工具、订阅制 SaaS、内部运营后台、带计费的多租户平台。它不适合纯静态展示站或无后端的简单页面——那会用它会显得重。
Quick Start

三步跑起来

拿到模板后，真正的上手动作只有三件：克隆、配环境、部署。下面按真实命令给出。

# 1) 克隆你购买的模板仓库（示例地址，以官网为准）
git clone https://github.com/your-org/mksaas-starter.git && cd mksaas-starter

# 2) 安装依赖（pnpm 优先，npm/yarn 亦可）
pnpm install

# 3) 本地启动开发服务器
pnpm dev          # 默认 http://localhost:3000
⚠️ 仓库地址与包管理器以你购买时拿到的说明为准。模板可能用 pnpm / npm / bun，package.json 里的 scripts 才是权威。
# 1) 复制环境变量模板
cp .env.example .env.local

# 2) 编辑并填入真实密钥（数据库 / 认证 / 支付 / AI）
#    DATABASE_URL、NEXTAUTH_SECRET、STRIPE_SECRET_KEY、OPENAI_API_KEY …
nano .env.local

# 3) 如有数据库迁移，先跑一次
pnpm db:push      # 或 npx prisma db push，依模板而定
# 方式 A：Vercel CLI 一键部署
pnpm dlx vercel          # 按提示登录并关联仓库
pnpm dlx vercel --prod   # 推到生产环境

# 方式 B：连 GitHub 到 Vercel 控制台，环境变量在后台逐一填写
# 之后每次 git push 即自动构建部署
💡 生产环境变量务必在 Vercel 后台填写，不要把 .env.local 提交进仓库。模板的 .gitignore 已默认忽略本地 env 文件。

📂 读目录

先打开 lib/ 与 app/，理解四类客户端与路由分组，再动手改 UI。

🧪 本地验证

pnpm dev 后走一遍注册→登录→调用 AI→订阅支付（测试模式）全链路。

🔒 安全自查

确认无硬编码密钥、webhook 验签、错误处理不泄漏内部信息后再上线。
