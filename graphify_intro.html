INTRO

① 它到底是什么？

Graphify 是一个 Claude Code 技能（skill），同时也兼容 Codex、OpenCode、Cursor、Gemini CLI、 Aider、Kilo、Devin、Kiro 等一大票 coding agent。你只要在任何目录里打一句 /graphify .，它就读遍该目录下的代码、SQL、R 脚本、shell、文档、论文、截图、白板照片， 甚至其他国家语言的图片，用 Claude 视觉 + AST 抽取出「概念」与「关系」，连成一张图。

本质是 GraphRAG（图谱增强检索）：把非结构化/多模态语料压成一张知识图谱，之后用 query / path / explain 去查，而不是每次把原始文件全塞进上下文。官方基准： 混合语料（代码+论文+图片）下，每次查询比直接读原文件省 71.5 倍 token。

💡 关键卖点不是"画图好看"，而是「诚实」：每条边都打标 EXTRACTED / INFERRED / AMBIGUOUS，让你一眼看出这是"原文实锤"还是"模型猜的"。

DEEP DIVE

④ 抽取层 extract.py 深读

extract.py 是这个项目里最大的文件（约 218KB），核心是每种类型一个抽取器 + 一个调度分发。 每种代码语言写 extract_<lang>(path) -> dict，统一返回如下 schema：

{
  "nodes": [
    {"id": "unique_string", "label": "human name",
     "source_file": "path", "source_location": "L42"}
  ],
  "edges": [
    {"source": "id_a", "target": "id_b",
     "relation": "calls|imports|uses|...",
     "confidence": "EXTRACTED|INFERRED|AMBIGUOUS"}
  ]
}

关键点：

  • 代码走 tree-sitter AST：pyproject 里钉了一长串 tree-sitter-* 语言（py/js/ts/go/rust/java/c/cpp/ruby/c#/kotlin/scala/php/swift/lua/zig/powershell/elixir/objc/julia/verilog/fortran/bash/json…），解析出函数、类、import。
  • 调用图第二遍（call-graph 2nd pass）：先抽显式 import/定义，再做一遍跨文件推理，把推断出的 calls 边标成 INFERRED——这就是"猜"的来源，但被如实标注。
  • 多模态：文档(.md/.txt/.rst)与论文(.pdf，做引文挖掘)走 Claude 抽概念；图片(.png/.jpg/…)走 Claude 视觉，截图、架构图、甚至外语手写白板都能抽。代码改动走 AST 不用 LLM，只有文档/图片才进 LLM 重抽。
  • schema 校验：validate.py 在 build_graph() 消费前强制校验格式，错的直接 raise，保证下游拿到的是合法图。
  • 去重：dedup.py + _minhash.py（MinHash）做语义级去重，避免把同一概念的不同表述变成一堆碎节点。
🧩 置信标签三档：EXTRACTED 原文显式（如 import 语句）； INFERRED 合理推断（调用图第二遍、共现）； AMBIGUOUS 不确定，在报告里单独标给你人工审。
DEEP DIVE

⑤ 建图 + 社区发现

build.py（约 52KB）把一堆抽取 dict 拼成 nx.Graph，处理节点合并、边去重、关系归一。 之后 cluster.py 做社区发现：用 Leiden 算法（graspologic 实现）给每个节点挂上 community 属性。

为什么是 Leiden 而不是 Louvain？Leiden 保证社区连通、不碎裂，更适合后面"按社区生成 Wiki 文章"—— 每个社区 = 一个知识主题 = 一篇 Wikipedia 风格条目。这对 GraphRAG 的检索质量很关键：agent 查图时可以先定位社区再读局部，而不是在全局里捞针。

  • 节点带 source_file / source_location，所以图谱是可溯源的——点开节点能跳回源码行。
  • 支持 SCIP 索引导入（scip_ingest.py）、Postgres schema 内省（pg_introspect.py）、 Google Workspace 文件——把"数据库 schema + 应用代码 + 基础设施"放进同一张图（README 的卖点）。
  • 兼容多图：multigraph_compat.py 处理平行边。
DEEP DIVE

⑥ 分析层 analyze.py

图建好后，analyze.py（约 28KB）产出三样"人话"洞察，写进 GRAPH_REPORT.md：

  • God nodes（枢纽节点）：度数最高的概念——所有东西都绕着它连，往往是系统的核心抽象。
  • Surprising connections（意外连接）：按复合评分排序，跨模态边（代码↔论文）权重高于代码↔代码，每条都附一句英文"为什么连"。这是 Graphify 最出彩处——跨文件/跨模态的隐藏关系。
  • Suggested questions（建议问题）：4–5 个"这张图最擅长回答"的问题，引导你用它。

此外还有 affected.py（改动某个文件会影响哪些）、reflect.py（反思/补全）、 global_graph.py（跨语料全局图）——偏向"agent 辅助导航"的能力。

OUTPUT

⑦ 输出与导出

export.py + callflow_html.py 一把梭产出整个 graphify-out/：

graphify-out/
├── graph.html       # 交互图（vis.js）：点节点/搜/按社区过滤
├── obsidian/        # 当 Obsidian 库打开
├── wiki/            # 每社区一篇 Wiki 文 + index.md（--wiki）
├── GRAPH_REPORT.md  # god节点/意外连接/建议问题
├── graph.json       # 持久图，几周后再查不用重读原文件
└── cache/           # SHA256 缓存，只重处理改动文件

支持的额外导出格式（CLI flag）：

  • --svg → graph.svg（matplotlib）
  • --graphml → graph.graphml（Gephi / yEd 可视化）
  • --neo4j → cypher.txt（导入 Neo4j；但默认不需要 Neo4j，纯本地 NetworkX 就够）
  • --mcp → 起 MCP stdio server（serve.py），让别的 agent 通过 MCP 直接查这张图
  • callflow_html.py → Mermaid 架构/调用流 HTML，给 agent 当"代码地图"
SYNC

⑧ 增量更新 / 缓存 / watch

  • --update：只重抽改动文件，合并进已有图。cache.py 用 SHA256（语义缓存）判断哪些文件变了，未变的直接复用。
  • --watch：后台常驻，文件一变就同步。代码保存→即时重建（只跑 AST，不调 LLM）；文档/图片改动→通知你跑 --update 做 LLM 重抽。多 agent 并行写代码时图能自动保持最新。
  • Git hook：graphify hook install 装一个 post-commit 钩子，每次 commit 后自动重建图。无需常驻进程，跟任何编辑器兼容，能和已有 hook 共存。
  • benchmark.py：跑 corpus vs subgraph 的 token 对比，自动打印压缩倍数。
SECURITY

⑨ 安全

所有外部输入先过 security.py 再使用（对应有 SECURITY.md 威胁模型）：

  • URL → validate_url() 只允许 http/https + _NoFileRedirectHandler 阻断 file:// 重定向（防 SSRF 把图导出成读本地文件）。
  • 抓取内容 → safe_fetch()/safe_fetch_text() 有大小上限和超时。
  • 图文件路径 → validate_graph_path() 必须解析在 graphify-out/ 内，防路径穿越。
  • 节点标签 → sanitize_label() 去控制字符、截 256 字符、HTML 转义（防导出 HTML 里注入）。

这让 Graphify 能安全地对"任意文件夹 + 任意 URL"做功，而不把用户机器暴露给恶意输入。

SKILLS

⑩ 多宿主技能（它的杀手锏）

仓库里有一堆 skill-*.md：skill-claude / skill-codex / skill-opencode / skill-kilo / skill-aider / skill-amp / skill-agents / skill-copilot / skill-claw / skill-droid / skill-devin / skill-kiro / skill-vscode / skill-pi / skill-trae …。每个是对应 coding agent 的"技能说明书"， graphify install 会按你用的宿主复制对应的进去。

意思是：同一套图谱引擎，能插进几乎所有主流 coding agent。你用 Claude Code 就 /graphify， 用 Codex/Cursor/Gemini 也各有一份等效技能。它本身就是"agent 的 agent 工具"。

还有 always_on/ 常驻注入块、skills/<host>/references/ 渐进式披露参考， 让图谱在 agent 会话里始终可用。

README 一句话总结技术栈：NetworkX + Leiden(graspologic) + tree-sitter + Claude + vis.js。 不需要 Neo4j、不需要服务器，完全本地跑。 LLM 适配在 llm.py（约 117KB）里，可选接 OpenAI / Anthropic / Gemini / Ollama / Bedrock / Kimi，还能跑 faster-whisper 抽视频字幕、jieba 切中文。

RUN IT

⑫ 怎么跑起来

pip install graphifyy && graphify install   # PyPI 暂用 graphifyy
# macOS 若报错 externally-managed，改用：
pipx install graphifyy

然后在任意目录打开 coding agent，输入：

/graphify .                 # 处理当前目录
/graphify ./raw --mode deep     # 更激进的 INFERRED 边
/graphify ./raw --update        # 只重抽改动
/graphify query "attention 和 optimizer 怎么连？"
/graphify path "DigestAuth" "Response"
/graphify ./raw --watch         # 文件变就自动同步
/graphify ./raw --wiki          # 生成 agent 可读 Wiki
/graphify ./raw --mcp           # 起 MCP server
graphify hook install           # 装 post-commit 钩子

支持的文件类型：代码(.py/.ts/.js/.go/.rs/.java/.c/.cpp/.rb/.cs/.kt/.scala/.php…)、 文档(.md/.txt/.rst)、论文(.pdf)、图片(.png/.jpg/.webp/.gif，外加 URL 抓取与 Postgres schema。

★ 一句话总结 ★

Graphify = tree-sitter/视觉多模态抽取 + NetworkX 图谱 + Leiden 社区发现 + 诚实的 EXTRACTED/INFERRED/AMBIGUOUS 标注，把"代码+论文+图片+数据库 schema"压成一张可溯源、可查询、 可导出成 Obsidian/Wiki/MCP 的知识图谱，且能作为 skill 插进几乎所有主流 coding agent。 它解决的是 Karpathy 那种 /raw 杂烩文件夹的"我到底存了啥"问题。▮
