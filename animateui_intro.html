Overview

它解决什么问题：让动画回到「写组件」本身

传统做法是手写 CSS keyframes 或在组件里挂载 useEffect 调用 Motion API——样板代码多、退场动画（unmount 时）尤其难写。Animate UI 把常见动效封装成声明式组件，包裹即生效。

🧩

声明式 API

用 FadeIn / SlideUp / Scale 等组件包裹目标元素，动画行为靠 props 表达，不再手写 keyframes。

↔️

入场 / 退场

元素挂载时淡入、卸载时淡出，退场过渡由组件托管，避免手动管理 unmount 时序。

🔁

循环动画

内置 loop 模式，适合 loading 指示、呼吸灯等需要无限循环的场景，无需自己写 animation-iteration。

🎯

触发控制

支持 scroll、hover、click、in-view 等触发方式，把动画绑定到用户交互或滚动位置。

🪶

体积小

gzip 约 3 KB 量级，仅依赖 Motion，不会显著拉高打包体积；比 ReactBits 更克制。

🧱

可组合

组件可嵌套，配合 delay prop 实现错落有致的连续动画，复合效果由组合而非新 API 产生。

Deep Dive

设计理念：声明式 + 基于 Motion 的薄封装

Animate UI 不是另起炉灶的动画引擎，而是在 Motion（原 Framer Motion）之上做的一层「组件化薄封装」。真正的动画计算、退场编排、可访问性（prefers-reduced-motion）都交给成熟的 Motion，库本身只负责把常见模式变成可读的 JSX。

  • 底层引擎是 Motion：位移、缩放、不透明度由 Motion 的 animate 驱动，性能与退场时序有社区验证。
  • 组件即动画：一个 <FadeIn> 等于「初始 opacity 0 → 1」的预设，省去重复声明初态/终态。
  • props 即配置：delay、duration、loop 等参数直接写在标签上，改一处即可调节奏。
  • 零额外心智负担：没有新的状态管理概念，组件卸载时自动处理退场，不残留定时器。
💡 选它的理由很直接：如果你的项目只想给卡片、列表、弹窗加「出现/消失」的润色，又不想为动画引入一整套设计系统，Animate UI 的「薄」就是它的核心优势。
Usage

上手用法：包一层组件就动起来

安装 animate-ui-react，用动画组件包裹任意子元素即可。下面是最典型的三种预设与错落延迟写法。

// 1) 安装
npm install animate-ui-react

// 2) 用组件包裹目标元素
import { FadeIn, SlideUp, Scale } from 'animate-ui-react';

function Card() {
  return (
    <FadeIn delay={0.1}>
      <SlideUp delay={0.2}>
        <Scale>Hello Animate UI</Scale>
      </SlideUp>
    </FadeIn>
  );
}
⚠️ delay 单位为秒（与 Motion 一致）。多个动画组件嵌套时，给内层递增 delay 即可形成「先淡入、再上滑、最后放大」的连续节奏，无需手动编排 Promise。

Comparison

它和 ReactBits、Framer Motion 怎么选

三者不是替代关系，而是不同抽象层。按「想要的掌控力 / 想写的代码量」取其一。

Framer Motion / Motion
底层引擎层

给需要完全自定义动画参数的场景。你能控制每一帧，但要手写初态/终态/退场逻辑，样板最多。

Animate UI
组件预设层

在 Motion 之上封装常见动效（淡入/上滑/缩放/循环）。想「包一层就动」、又想比 ReactBits 更轻，选它。

ReactBits
组件 + 模板层

更全的动画/特效组件合集，覆盖面广但体积更大。项目需要大量花哨特效时可上，否则 Animate UI 更克制。

FAQ

常见问题

关于体积、依赖、退场动画与选型的高频疑问。

01

Animate UI 依赖什么？会拉进很重的包吗？

＋
唯一的运行时依赖是 Motion（原 Framer Motion）。库本身就是一层薄封装，gzip 体积约在 3 KB 量级，不会显著拉高打包体积——这也是它相比 ReactBits 更「轻」的原因。
02

它和 Framer Motion 是什么关系？

＋
Animate UI 运行在 Motion 之上，是对常见动效的「组件化预设」：
  • 想完全自定义每一帧 → 直接用 Motion
  • 想用声明式组件快速加动效 → 用 Animate UI
  • 两者可并存，Animate UI 不屏蔽底层 Motion 能力
03

退场（unmount）动画怎么处理？

＋
由组件托管。你只需把元素包进动画组件，组件内部在卸载前播放退场过渡，再真正移除 DOM——不需要你手写 useEffect + 定时器去延迟 unmount。
04

支持 React 18 之外的版本吗？要用 TS 吗？

＋
面向 React 18+ 的现代 React 项目，普通函数组件即可使用。它提供声明式 JSX 组件，TypeScript 项目能直接拿到 prop 类型提示，无需额外配置。
05

能在 ReactBits 与 Animate UI 之间二选一吗？

＋
可以二选一，不必都装。准则：
  • 只要少量入场/退场/循环润色 → Animate UI 更轻
  • 需要大量特效组件与模板 → ReactBits 覆盖更全
  • 两者都不想引入重依赖 → 直接用 Motion 手写
06

循环动画会一直占主线程吗？

＋
循环类动画（如 Loop）由 Motion 驱动，走 GPU 友好的 transform/opacity 属性，开销很低。仍建议用 React DevTools Profiler 抽样检查，避免在列表里对成百上千个元素同时开循环动画。
Quick Start

两分钟上手

装包 → 引入组件 → 包裹元素。下面给出真实安装命令与一个最小可用示例。

# npm
npm install animate-ui-react

# 或 pnpm
pnpm add animate-ui-react

# 或 yarn
yarn add animate-ui-react
⚠️ 包名是 animate-ui-react（不是 animate-ui）。安装前确认项目已是 React 18+。
import { FadeIn, SlideUp } from 'animate-ui-react';

export default function App() {
  return (
    <main>
      <FadeIn delay={0.1}>
        <h1>欢迎</h1>
      </FadeIn>
      <SlideUp delay={0.25}>
        <p>这一段会向上滑入。</p>
      </SlideUp>
    </main>
  );
}
💡 跑起来后用 React DevTools Profiler 抽查渲染开销；需要无限循环时换用 Loop 组件，需要交互触发时挂 hover/click/in-view 类 props。
