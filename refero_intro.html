Overview

它不是「又一个灵感站」，而是一套可检索的设计证据库

Deep Dive

三个角度，把 Refero 用透

从"怎么搜"到"怎么沉淀"，再到"怎么接进 AI 工作流"——下面是可落地的真实用法，不是泛泛而谈。

① 语义搜索：用一句话找到对的界面

关键词搜索要求你先知道"它叫什么"；Refero 的语义搜索反过来——你描述场景，它返回真实产品里解决同一问题的截图。下面是送给 AI 编码 agent 的调研 prompt 模板，可直接复用：

# 把"要找的界面"写成调研指令，贴给编码 / 设计 agent
你正在设计 一个 "用户删除账户前的二次确认" 流程。
请先在 Refero (https://refero.design) 检索真实产品怎么做，
重点关注 这三种模式：

  1. destructive-action  —— 直接弹确认框拦截危险操作
  2. confirm-modal      —— 输入文字 / 勾选后才能继续
  3. undo-window       —— 先执行、留 10 秒可撤销窗口

# agent 应返回：每个模式 2–3 个真实产品截图 + 取舍建议
# 输出形态（概念 response）：
{
  "query":   "account deletion confirm",
  "hits": [
    { "product": "Notion",  "pattern": "destructive-action" },
    { "product": "GitHub", "pattern": "confirm-modal" },
    { "product": "Linear", "pattern": "undo-window" }
  ]
}
"空状态怎么引导首次使用" "定价页三档如何排布" "移动端底部导航样式" "表单报错 inline 还是 toast"

Refero 的价值不止"看"，更在"存"和"用"。一个项目从 0 到可交付的标准路径：

Refero 采用免费 + 付费的双档模式，付费主要解锁更高的搜索额度、更全的库访问与团队共享能力。

FAQ

关于 Refero，你大概率会问的

01

Refero 到底是什么，和 Dribbble、Pinterest 有何不同？

＋
Dribbble / Pinterest 上大量是设计师主动上传的概念稿、美化稿，好看但常脱离真实工程约束。Refero 只收真实上线产品的界面截图，并按 UI 模式（onboarding、pricing、settings…）结构化归类，还提供 AI 语义搜索。一句话：前者是"灵感审美"，Refero 是"可对照的设计证据"。
  • 来源：真实 App / 网站，不是 mockup
  • 组织方式：按交互模式，而非按美观度
  • 检索：自然语言语义搜索，而非只能猜标签
02

截图来自真实产品，会不会有版权 / 商用问题？

＋
Refero 的截图用于设计研究与内部参考是其主要定位。但把任意单张截图直接当素材用于对外发布的产品，仍需注意：
  • 研究、学习、做竞品对照 → 通常在其使用条款允许范围内
  • 直接复制某产品的视觉去上线 → 有侵权与品牌混淆风险，应避免
  • 对外发布前，建议把参考"转译"成自己的设计语言，而非照搬
具体以 Refero 官网当前服务条款为准，本页不构成法律意见。
03

AI 语义搜索到底怎么用？给个具体例子

＋
你不用记"它叫 pricing table 还是 pricing card"。直接在搜索框描述场景，例如：
  • "引导免费用户升级的定价页，三档、中间档高亮"
  • "移动端登录失败后的 inline 报错样式"
  • "空购物车时的插画 + 行动按钮组合"
Refero 会返回一批真实产品里解决同一问题的截图，你再对照挑范式，而不是凭空拍板。
04

免费版和 Pro 有什么区别？

＋
两者功能一致，差异主要在额度与库深度：
  • Free：可浏览库、有限次搜索 / 采集，适合个人轻量调研
  • Pro：更高搜索额度、更完整库访问、浏览器插件与团队板共享
  • Team：在 Pro 之上加多人共享板、评论与统一管理
若你只是偶尔找参考，Free 已够用；高频调研或团队协作再上 Pro / Team。
05

怎么把 Refero 接进 AI 辅助设计 / 编码，减少返工？

＋
核心心法是"先调研、再生成"：
  • 写代码前，先在 Refero 检索目标界面的 2–3 个真实范式
  • 把截图链接 + "采用模式 X、规避模式 Y"写进给 AI agent 的 prompt
  • 让模型基于真实参照生成，而不是从零发明布局，避免低级返工
这正是 Refero 被归为"面向 AI 时代设计研究平台"的原因——它把调研产物变成 AI 能消费的明确约束。
06

有浏览器插件 / API / Figma 插件吗？

＋
Refero 主推浏览器插件采集（看到好设计一键存进自己的板子），Web 端提供搜索与整理。公开资料重点在"采集 + 语义搜索 + 共享板"这条主线；API 与 Figma 插件等深度集成请以官网当前功能列表为准，本页未对此做独立核验，避免给出过时结论。
Quick Start

三条上手路径，挑最顺手的

最省事的是直接上官网搜；想沉淀个人库就装浏览器插件；要把调研喂给 AI 工作流，走第三条。

# 1) 打开官网
浏览器访问 https://refero.design

# 2) 用自然语言检索（不用猜关键词）
搜索框输入 "用户删除账户前的二次确认弹窗"

# 3) 按 UI 模式对照，挑 2–3 个真实产品范式
浏览 destructive-action / confirm-modal / undo-window 三类结果

# 4) 把选中的截图钉进项目板，留一句取舍理由
⚠️ Free 档对搜索 / 采集次数有限额。若只是偶尔找参考足够；高频调研再考虑 Pro。
# 1) 安装浏览器插件（Chrome 等）
在 Refero 官网或插件商店 添加 Refero 扩展

# 2) 看到好设计，一键存进自己的板子
在任意网页点开插件 → "Save to board"

# 3) 回到 Web 端按项目板归拢
打开 refero.design → 选择项目板 → 打语义标签

# 4) 邀请协作者共同编辑 / 评论
分享板链接 → 团队在真实参照上对齐
# 把 Refero 调研结果转成给 AI 编码 agent 的约束
任务: 实现"删除账户"确认流程
参照(Refero 检索所得):
  - Notion  → destructive-action 拦截
  - GitHub  → confirm-modal 二次输入
  - Linear  → undo-window 10s 撤销
决策: 采用 confirm-modal，理由——误删成本最高
要求: 输出含错误态、移动端适配的 React 组件

# 这样模型基于真实范式生成，返工率显著低于凭空起稿
💡 把"采用哪个模式 + 为什么"写进 prompt，比只贴截图链接更稳——模型有了明确取舍，不会在多个范式间摇摆。
