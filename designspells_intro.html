01 · 分类体系

四类标签，覆盖一个细节的两面

Design Spells 用「设备形态」和「交互性质」两条轴给案例贴标签，先定场景再定动作，避免大海捞针。

Mobile · 手机端细节 Desktop · 桌面端细节 Interaction · 交互反馈 Animation · 动效转场

📱 Mobile

下拉刷新、手势滑动、底部抽屉、触觉反馈等手机特有的「小动作」。

🖥️ Desktop

悬停态、右键菜单、光标跟随、窗口缩放时的布局过渡等桌面惯例。

✨ Interaction

点击、长按、拖拽后的即时反馈——让用户「知道系统听懂了我」。

🎞️ Animation

进场 / 退场 / 共享元素转场，让状态切换有连续感而非硬切。

⏳ Loading

骨骼屏、进度环、乐观更新等「等待不无聊」的占位策略。

🔔 Notification

Toast、红点、角标微动效——把「有消息」讲得轻而不吵。

03 · 动手复现

把它「看会的」变成「写会的」

微交互大多由一段 CSS 加少量 JS 构成。下面两个是 Design Spells 上最常见的两类细节，可直接拷进项目跑。

骨骼屏微光（Loading 类）

加载占位时从左到右扫过的渐变，比转圈圈更「高级」。核心是一段会动的 linear-gradient 背景。

/* 骨骼屏微光：加载占位时扫过的渐变 */
.skeleton {
  background: linear-gradient(90deg,#e9e9ef 25%,#f5f5f7 37%,#e9e9ef 63%);
  background-size: 400% 100%;
  border-radius: 10px;
  animation: shimmer 1.4s ease infinite;
}
@keyframes shimmer {
  0%   { background-position: 100% 0; }
  100% { background-position: 0 0; }
}

点赞弹簧（Interaction 类）

点击时放大回弹，给用户「按下去有反应」的即时确认。用 CSS 缓动曲线 + 一个 class 切换即可。

// 点赞弹簧：点击放大回弹
const btn = document.querySelector('.like');
btn.addEventListener('click', () => {
  btn.classList.add('pop');
  setTimeout(() => btn.classList.remove('pop'), 350);
});

/* .like.pop { transform: scale(1.35); transition: transform .35s cubic-bezier(.2,1.4,.4,1); } */
💡 复现优先于收藏：Design Spells 的价值不在「存了一堆动图」，而在你照着写一次后，下次遇到同类需求能直接调出思路。建议每看一个案例，至少手写其中一段关键代码。
04 · 它和别的灵感站有什么不同

不是图库，是「教学切片」

同样找灵感，Dribbble / Mobbin / Pinterest 解决「看得多」，Design Spells 解决「看得懂、写得会」。

  • vs Dribbble：Dribbble 多为概念稿、视觉先行；Design Spells 只收已上线真实产品的细节，强调「可复现」而非「好看」。
  • vs Mobbin：Mobbin 按 App 整屏截图归档，适合看完整流程；Design Spells 把单点微交互单独切片，更适合补「小细节」。
  • vs Pinterest：Pinterest 靠算法投喂、信息杂；Design Spells 人工策展、标签有限但精准，没有信息噪音。
  • 共同点：三者都适合做调研起点，但落地到代码时，Design Spells 的「动图 + 溯源」组合最省从图到实现的翻译成本。
FAQ

常见问题

关于内容来源、使用方式、投稿与订阅的高频疑问。

01

Design Spells 里的案例是真实的吗？

＋
是的，案例来自 Apple Sports、Snapchat、Dropbox 等已上线的真实产品，强调「真实细节」而非概念稿。每个案例都会标注来源 App 与对应功能，方便你回原产品对照。
  • 优势：你复现的是被真实用户验证过的交互，不是作者脑补的「应该好看」。
  • 注意：具体实现细节（代码）由你自己补齐，站点提供的是「看什么、为什么」。
02

标签分类是怎么组织的？

＋
用两条轴交叉：设备形态（Mobile / Desktop）与交互性质（Interaction / Animation）。你既可以「我只看手机端的动效」，也可以「我只看所有加载态」，组合筛选快速定位。
  • Mobile / Desktop —— 决定交互发生在什么屏幕。
  • Interaction / Animation / Loading / Notification —— 决定细节属于哪一类动作。
03

怎么把一个案例用到自己的项目里？

＋
流程是：点开卡片看动图 → 读详情理解触发条件与业务含义 → 在自己的项目里用 CSS / JS 复现核心一段。站点本身不提供现成组件代码，它的定位是「灵感切片 + 原理讲解」，落到工程由你完成。建议先看动图里的时序（时长、缓动、先后），再写代码对拍。
04

我可以投稿自己发现的好细节吗？

可以。站点提供 Submit 入口，发现优秀的设计细节即可投稿分享，库随社区贡献持续扩充。投稿时最好附上：来源 App 名称、触发该交互的具体操作、以及一段动图 / GIF，便于审核与复现。
05

如何持续获取新案例？

＋
通过 Newsletter 订阅，站点会定期（约每周）推送新增案例，不用天天刷首页。订阅后你拿到的是「精选增量」，比在信息流里被动刷更高效。
06

它适合谁用？

＋
主要两类人：
  • 前端开发者：把「想做但说不清」的动效，对照真实案例拆成可写的交互。

Quick Start

三步上手：看、藏、复现

不用注册也能浏览全部案例；下面是把灵感变成你工程的几段可直接用的代码。

// 下拉刷新指示：滚动到顶继续下拉时拉伸回弹（移动端常见）
let startY = 0;
const box = document.querySelector('.feed');
box.addEventListener('touchstart', e => startY = e.touches[0].clientY);
box.addEventListener('touchmove', e => {
  const dy = e.touches[0].clientY - startY;
  if (box.scrollTop === 0 && dy > 0) {
    box.style.transform = `translateY(${Math.min(dy * 0.4, 80)}px)`;
  }
});
box.addEventListener('touchend', () => box.style.transform = '');
⚠️ 这只是「原理骨架」。真实 App 里还要处理阈值触发、加载态、阻尼曲线与无障碍（reduced-motion）。对照 Design Spells 的动图把时序对上，再补这些边界。
// 用 localStorage 自建一个 Design Spells 收藏夹
const KEY = 'ds_favs';
function save(id, title) {
  const list = JSON.parse(localStorage.getItem(KEY) || '[]');
  list.push({ id, title, at: Date.now() });
  localStorage.setItem(KEY, JSON.stringify(list));
}
function list() { return JSON.parse(localStorage.getItem(KEY) || '[]'); }
