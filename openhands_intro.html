INTRO

① 它到底是什么？

OpenHands（前身 OpenDevin）是一个开源的「通用 AI 软件工程师」平台。 它的目标不是只做一个聊天机器人，而是让 LLM 真正像人一样去操作一台电脑： 开终端跑命令、写/改文件、起 Jupyter 跑 Python、用浏览器查资料、调 API、提 PR。

核心论文 OpenHands: An Open Platform for AI Software Developers as Generalist Agents (arXiv:2407.16741) 把它概括为三个可插拔的支柱：Agent 抽象、Event Stream 事件流、 Runtime 运行时。这三者通过事件流解耦，所以前端、后端、沙箱、agent 可以分别演进、分别部署。

⚠️ 重要背景：这个仓库正在发生大拆分。README 顶部明确写着 "The code in this repo is moving!"。 原来庞大的 openhands/ 包（agent / runtime / controller）已经被抽进独立的 software-agent-sdk 仓库；本仓库现在主推 Agent Canvas（自托管的 agent 控制面板）。 下文会同时讲「历史经典架构」和「现在的 V1 形态」。

③ 三大件架构

AGENT

读事件流 → 调 LLM → 产出 Action
»

EVENT STREAM

只追加日志 (append-only log)
»

RUNTIME

Docker 沙箱里执行 → 回 Observation

这是整张图的灵魂：一切皆事件 (Action / Observation)。Agent 不直接碰环境，而是把「意图」写成 Action 丢进事件流；Runtime 订阅事件流、在沙箱里执行、再把「结果」写成 Observation 丢回来。 控制台、前端、监控服务都是事件流的订阅者 (subscriber)，彼此完全解耦。

事件按「是否给 LLM 看」分两类：

ActionEvent 工具调用 MessageEvent 人说的话 ObservationEvent 执行结果 UserRejectObservation 被拒 CondensationRequest 压缩请求 PauseEvent 用户暂停

→ act/obs 类会进 LLM 上下文；int 内部事件只给框架用，不喂给模型。

DEEP DIVE

④ 事件流 EventStream 深读

代码里真正的实现是 openhands/events/stream.py 中的 EventStream(EventStore)。 它不是简单的 list，而是一个带订阅、带持久化、带线程池的发布/订阅总线。

# 核心字段（精简自真实源码）
class EventStream(EventStore):
    _subscribers: dict[str, dict[str, Callable]]   # 订阅者ID -> 回调集合
    _queue: queue.Queue[Event]                       # 跨线程事件队列
    _queue_thread: threading.Thread                  # 后台消费线程
    _thread_pools: dict[...]                            # 每个回调一个独立 event loop
    _write_page_cache: list[dict]                     # 分页缓存，避免逐条读盘

几个值得玩味的设计点：

  • 每个订阅者独占一个线程 + 独立 asyncio event loop。这样 AgentController、Runtime、Memory、Server 可以在不同线程里并发处理同一个事件，互不阻塞。
  • 写入走「分页缓存」：事件先攒成一页（cache_size 条）再整页 JSON 落盘， 事件很多时比逐条写快得多。单条事件超过 ~1MB 会打 warning。
  • 秘密替换：_replace_secrets() 把 token/密码在落盘前替换成 <secret_hidden>，避免把 API key 写进事件日志。
  • subscriber 枚举：AGENT_CONTROLLER / RUNTIME / MEMORY / SERVER / RESOLVER / MAIN， 谁都能 subscribe(id, callback) 监听全量事件——这就是插件化监控的基础。
💡 控制流也是事件：早期 PR (#1538) 把「暂停/恢复/停止」也统一成 ChangeAgentStateAction → AgentStateChangedObservation， 前端改状态不再需要特殊通道，全部走同一条事件总线。
DEEP DIVE

⑤ Agent 内核：CodeAct 循环

主角是 CodeActAgent，思路来自 CodeAct 论文：与其让模型输出 JSON 工具调用， 不如让模型直接输出可执行的代码（bash / Python），因为代码本身就是最强、最灵活的工具接口。

论文里给了一个极简 agent 骨架，正好看懂主循环：

class MinimalAgent:
    def reset(self):
        self.system_message = "You are a helpful assistant..."

    def step(self, state: State):
        messages = [{'role':'system', 'content': self.system_message}]
        for prev_action, obs in state.history:   # 把历史事件流还原成 LLM 消息
            messages.append(get_action_message(prev_action))
            messages.append(get_observation_message(obs))
        response = self.llm.do_completion(messages)   # 调 LLM
        action = self.parse_response(response)         # 解析意图
        if   self.is_finish_command(action): return AgentFinishAction()
        elif self.is_bash_command(action):   return CmdRunAction(command=action.command)
        elif self.is_python_code(action):   return IPythonRunCellAction(code=action.code)
        elif self.is_browser_action(action):return BrowseInteractiveAction(code=action.code)
        else: return MessageAction(content=action.message)

真实 AgentController（openhands/controller/agent_controller.py）在这个循环之上加了：

  • max_iterations / max_budget：步数和美元预算上限，超了就停。
  • SecurityAnalyzer：每个 Action 先做风险评估；没配分析器时按 fail-safe 一律当 UNKNOWN 风险处理，确认模式下必须人工放行。
  • StuckDetector：检测到模型在死循环就自动触发恢复。
  • 多 Agent 委派：本体可以 spawn delegate controller，子任务跑完把结果交回父控制器。
  • Condenser（记忆压缩）：上下文太长时，发 CondensationRequest， 把旧事件摘要成 CondensationSummaryEvent，腾出窗口——这是长任务不爆 context 的关键。
🧠 State 不只是事件流，还装着：累计 LLM 花费、多 agent 委派元数据、当前 agent 状态、 start_id（断点续跑入口）等。事件流 + 这些辅助字段 = 一次会话的完整可恢复快照。

⑥ Runtime：Docker 沙箱里发生了什么

每次任务，OpenHands 起一个隔离的 Docker 容器当沙箱，用户的 workspace 目录挂载进去。 容器里跑一个 Action Execution Server（REST API），后端通过它发 Action、收 Observation。

  • 任意镜像支持：用户给任意 Docker 镜像，OpenHands 自动 build 出带 runtime client 的 _od 镜像，因此不再依赖 ssh——容器里直接用 pexpect 维持 bash 会话， cwd / 环境变量都是有状态的。
  • 插件系统：插件继承基类 Plugin，在 runtime/plugins/__init__.py 的 ALL_PLUGINS 注册； Agent.sandbox_plugins 声明要加载哪些（如 Jupyter、agent-skills）。
  • 多 runtime 后端：DockerRuntime / LocalRuntime / RemoteRuntime / E2BRuntime / K8s / Modal / Daytona，同一套接口随便换。
  • 端口分配：用文件锁在固定区间找可用端口（runtime 主端口、VSCode 端口、web app 端口）， 浏览器观测还能返回 HTML / DOM / 无障碍树 / 截图。
2026 现状

⑦ 正在发生的重构：V1 / Agent Canvas

本仓库现在定位为 「自托管的 agent 控制中枢 (developer control center)」， 即 Agent Canvas。它把 AI agent 变成一支「永远在线」的工程小队，可接： OpenHands 自带 agent、Claude Code、Codex、Gemini，或任何支持 ACP（Agent-Client Protocol）的 agent。

  • 架构分层：Agent Canvas 前端 ↔ Agent Server（REST API，跑多个 agent）↔ 可选 Automation Server（定时/Webhook 触发）。
  • agentic 内核已外置：原来 openhands/ 里的 agent / runtime / controller 抽进了 OpenHands/software-agent-sdk（即 openhands-sdk / openhands-agent-server / openhands-tools，pyproject 里固定 ==1.35.0）。
  • 本仓库剩下什么：openhands/server、openhands/app_server、 openhands/db（Postgres/SQLAlchemy）、frontend（React+Vite）、 以及 skills/。
  • 多后端切换：本地笔记本、Mac Mini、云 VM、OpenHands Cloud 都能当 backend， 同一个 Canvas 前端一键切换，团队可共用一个 Agent Server 做 code review / 依赖升级。

SKILLS

⑨ Skills / Microagents

仓库根目录的 skills/ 是一堆 Markdown「技能卡」，agent 在合适场景会自动加载， 相当于给模型注入领域 SOP。例如：

  • code-review.md / codereview-roasted.md —— 代码评审（后者是吐槽风 😈）
  • github.md / gitlab.md / bitbucket.md / azure_devops.md —— 各平台操作
  • agent-builder.md / add_agent.md —— 让 agent 自己造子 agent
  • agent_memory.md —— 长期记忆用法
  • docker.md / kubernetes.md / ssh.md / swift-linux.md —— 环境相关
  • fix_test.md / fix-py-line-too-long.md / update_pr_description.md —— 工程杂活

还有 microagents 概念：仓库级 .openhands/microagents/ 放「这个仓库的上下文」， 任务级 microagent 放「这个具体任务的指令」，agent 启动时自动召回，等于把 RAG 塞进了事件流。

RUN IT

⑩ 怎么跑起来

方式一：Docker 沙箱（最推荐，隔离最干净）

export PROJECTS_PATH="$HOME/projects"
docker run -it --rm -p 8000:8000 \
  -v "$HOME/.openhands:/home/openhands/.openhands" \
  -v "${PROJECTS_PATH}:/projects" \
  ghcr.io/openhands/agent-canvas:1.0.0-rc.11

方式二：免沙箱直跑（⚠️ agent 能碰你整台机器的文件系统！）

npm install -g @openhands/agent-canvas
agent-canvas            # 完整本地栈
# 也可拆开：
agent-canvas --frontend-only
agent-canvas --backend-only

方式三：从源码（Vite 前端 + Python 后端）

git clone https://github.com/OpenHands/agent-canvas.git
cd agent-canvas && npm install && npm run dev

跑起来后访问 http://localhost:8000，在 UI 里加 LLM key、选 backend 即可开聊。

★ 一句话总结 ★

OpenHands = 事件流总线 + CodeAct 式 agent 循环 + Docker 沙箱执行器， 用「一切皆事件」把模型、环境、UI 彻底解耦；如今它正裂变成 Agent Canvas 控制面板 + 独立 SDK 内核， 朝着「自托管的、永远在线的 AI 工程小队」演进。▮
